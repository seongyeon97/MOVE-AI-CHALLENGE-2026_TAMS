# S&E Driving — 화물차 안전운전 앱 프로토타입

스크린샷 기반으로 구현한 바닐라 HTML/CSS/JS 웹앱입니다. 빌드 도구 없이 바로 브라우저에서 동작합니다.

## 실행 방법

폰트(`@font-face`)와 로고/트럭 이미지를 상위 폴더(`../reference`, `../font`)에서 상대경로로 불러오기 때문에,
**로컬 서버로 실행하는 것을 권장**합니다 (일부 브라우저는 `file://`로 직접 열면 폰트를 막을 수 있음).

프로젝트 루트(`국토부 해커톤` 폴더)에서:

```bash
# Python이 있는 경우
python -m http.server 8000

# Node가 있는 경우
npx serve .
```

그다음 브라우저에서 `http://localhost:8000/app/index.html` 접속.

(급하면 `app/index.html`을 그냥 더블클릭해서 열어도 대부분 크롬에서는 정상 동작합니다.)

## 다른 PC로 옮겨서 보기 — 단독 실행 HTML

`app/`, `reference/`, `font/`를 폰트·로고·트럭 이미지·Three.js까지 전부 인라인으로 합쳐 파일 하나로 만들면
서버 없이 더블클릭만으로 다른 PC에서 그대로 열립니다(로그인/타이어 상세 등 mock 기반 기능은 완전히 오프라인
동작, 홈 화면 실시간 날씨만 인터넷 필요 — 연결이 없으면 현재 시각 기준 맑음으로 자동 대체). 이 저장소에는
빌드 스크립트도 산출물도 포함돼 있지 않습니다(별도로 필요하면 요청해서 생성).

## 구조

```
app/
  index.html      로그인 / 회원가입 화면 (정적 마크업) + 메인 앱 셸(헤더/콘텐츠/하단내비)
  css/style.css   디자인 토큰(라이트/다크 테마), 컴포넌트 스타일
  js/app.js       상태(mock data), 라우팅, 렌더링, 이벤트 처리
```

메인 앱(정비 대시보드 이하 전체 화면)은 `js/app.js`에서 템플릿 문자열로 렌더링됩니다.
로그인/회원가입만 정적 HTML이고, 나머지 화면(정비 현황 / 엔진오일·통합단말기·타이어 상세 / 오일 교체 등록 / 운행 / 설정)은
`state.vehicle` 객체를 기반으로 매번 새로 그려집니다.

## 구현된 화면

하단 내비게이션: **홈 · 운행 · 정비 · 알림 · 설정** (로그인 후 기본 화면은 홈). 모든 메인 화면 헤더 우측 상단에 CI 로고가 표시됩니다
(배경 없이 카드 색과 자연스럽게 섞이도록 `mix-blend-mode`로 처리, 크기도 키움). 로그인/홈/타이어 상세 화면은 스크롤 없이 한 화면(뷰포트)에 꽉 차도록 맞춰져 있습니다.

- 로그인 / 회원가입 (계정 정보 + 차량 등록 2단계, 라이트/다크 모두 대응)
  - 로그인 화면은 스크롤 없이 한 화면에 꽉 차며, 로고는 중앙 정렬 + 배경이 자연스럽게 섞이도록(`mix-blend-mode`) 처리하고 적당한 크기로 표시
    (아티팩트 빌드에서는 로고를 JPEG가 아니라 원본 PNG 그대로 임베드해 압축 아티팩트 없이 깨끗하게 나오도록 함)
  - 로그인 폼 하단에 회색 글씨로 데모 계정 안내를 두 줄로 표시("데모 버전 로그인 정보" / "ID : glovis / PW : 1234") —
    실제로는 아무 값이나 입력해도 로그인되며(서버 인증 없음), 이 ID/PW는 화면에 보여주기 위한 안내 문구일 뿐 실제로 검증하지는 않음
  - 차량등록증 사진을 첨부하면 차량번호·차대번호·주행거리·최종점검일을 자동 인식(시뮬레이션)하고,
    인식 실패 시 또는 "사진 없이 직접 입력할게요"를 누르면 수기 입력 폼이 나타남
  - 현재 누적 주행거리는 탭하면 하단에서 커스텀 숫자 키패드가 올라옴
  - **닉네임** 입력란(계정 정보 카드 최상단) — 홈 화면 인사말("안녕하세요, OO님")에 아이디 대신 이 닉네임이 표시됨
  - 폼 맨 아래 **개인정보 수집·이용 동의** 체크박스 — 체크해야만 "가입 완료" 버튼이 활성화됨(그 전엔 disabled)
  - 가입 완료 시 로그인 화면으로 돌아가고 방금 만든 아이디가 자동으로 채워짐
  - 회원가입 화면 좌측 상단에 뒤로가기 버튼(로그인 화면으로 이동)
- **홈**: 헤더는 차량번호만 표시(최종점검일은 뺌, 다른 화면과 높이만 맞춤). 인사말은 회원가입 때 입력한 **닉네임**을 사용(닉네임이
  없으면 아이디, 그것도 없으면 "게스트"). 로그인 성공 시 공지사항 팝업(아이콘·강조 텍스트는 빨간색, "확인하기" 버튼 — 자세한 확인
  로직은 아래 "공지사항 확인 흐름" 참고) + 내 트럭 사진 박스(16:9 비율 — 기존 21:9보다 세로로 더 길게 조정, 실시간 날씨 애니메이션
  배경 + 우측 상단 날씨 배지, 자세한 내용은 아래 "실시간 날씨 배경" 참고) + 운행 / 정비 바로가기 카드
  (세로형 2열 그리드, 스크롤 없이 한 화면에 꽉 참). 정비 카드 제목 옆에는 우수/양호/점검 필요 판정 배지가 함께 표시됨
- **안전 운행 현황**(헤더 타이틀 — 하단 내비 라벨은 그대로 "운행"): 헤더에 차량번호(전용 아이콘) + 전월 운행 km. 첫 카드는
  점수 게이지와 `reference/medal_*.png` 등급 이미지를 가운데 정렬로 나열하고, 이미지 바로 아래에 "상위 00%"를 적음. 그 아래로
  운행 건수·총 km·평균속도·급제동 횟수, 그리고 평가기간/기준일(줄바꿈 적용). 둘째 카드는 일자별 운행 기록 리스트(출발~도착·km·
  점수·등급·상세 화살표)이며, 우측 상단 드롭다운으로 조회할 월을 바꿀 수 있음(목업 데이터가 있는 달만 표시)
  - **메달(GOLD/SILVER/BRONZE)은 점수가 아니라 백분위로 정합니다** — `medalTierFromPercentile()`(`js/app.js`)이
    `driveRecord.percentile`(상위 몇 %인지, 현재 35%로 SILVER 구간)을 보고 상위 20% 미만 GOLD · 20~50% SILVER ·
    50% 초과 BRONZE로 판정합니다. 옆의 "OO점" 숫자·색조(양호/주의/위험)는 여전히 `scoreGrade()`가 절대 점수로 매기므로,
    점수와 메달은 서로 다른 두 기준(절대 점수 vs 동료 대비 순위)이라는 점을 기억해 두세요.
- **정비**: 트럭 그림이 최상단, 항상 **3D**로 표시(Three.js 프로시저럴 트럭, 드래그로 360° 회전) — 회원가입에서 고른
  6휠/8휠(기본값 6휠)에 따라 축 개수·카고박스 길이가 실제로 달라짐. (날씨 애니메이션은 홈 화면으로 이동했고, 이 박스는 3D 트럭에만 집중)
  헤더 우측 상단 CI 로고 왼쪽에 있던 편집(연필) 아이콘은 삭제 — 차량번호 수정은 설정 화면에서만 가능.
  하단에 정비 예약 현황 카드 + "정비소 예약하기" / "기본 정비 이력 현황" 버튼
  - 엔진오일 상세 (교체 이력, 거리/기간 기준 소진율 게이지 — 실제 날짜/주행거리로 계산됨) → **자가 점검**(체크리스트 + 제출하기) →
    오일 교체 등록(영수증 드롭존) / 정비소 예약 / 점검 리포트 보기
  - 통합단말기 상세 (신호 세기, **자가 점검** 체크리스트 + 제출하기 버튼, 정비소 예약 / 점검 리포트 보기)
  - 타이어 상세도 통합단말기·엔진오일과 동일하게 **자가 점검**(공기압·트레드 마모·이물질 박힘 체크리스트 + 제출하기) +
    **타이어 교체 등록**(오일 교체 등록과 동일한 패턴 — 교체 위치 선택 드롭다운 + 영수증 사진 드롭존 + 교체일 + 교체 시 주행거리,
    등록하면 해당 위치의 최근 교체일/주행거리가 갱신됨) + 정비소 예약 / 점검 리포트 보기 버튼을 갖춤
    - topdown 이미지를 크롭·투명도 낮춰서 6휠/8휠 모두 스크롤 없이 한 화면에 다 보이게 하고, 위치(1~4열 좌/우, 1열은
      운전석/조수석)별 상태를 큼직한 라벨로 상시 확인 (위치·상태·최근 교체일), 정상/점검 필요/교체 필요는 색으로 구분(초록/노랑/빨강).
      **운전석 위치를 나타내는 핸들 아이콘은 1열 좌측(운전석) 바퀴의 오른쪽, 실제 운전석이 있는 캡 안쪽**에 배치.
      공기압/마모율 대신 **교체 주기 기준**(60,000km/36개월)으로 판정
    - 휠 위치 점(hotspot)의 x/y 좌표는 `reference/*_truck_*wheel_topdown.png` 그림의 실제 바퀴 위치를 픽셀 단위로 측정해서 맞춘 값입니다
      (`renderTireDetailTruck()`의 `rows` 배열, 6휠/8휠 각각 따로). 그림을 다시 교체할 경우 이 좌표도 함께 재보정해야 합니다.
    - 라벨(이름표)은 트럭 이미지 박스(`#tire-truck-stage`, `overflow:hidden`)의 자식이 아니라 별도의 `.tire-label-overlay`
      레이어(같은 크기로 겹쳐진 형제 요소, `overflow` 제약 없음)에 그려집니다 — 바퀴 위치에 맞춰 점을 화면 가장자리 쪽으로 옮기면
      라벨 텍스트가 이미지 박스 밖으로 나가면서 잘릴 수 있는데, 이 구조 덕분에 잘리지 않고 항상 전체가 보입니다.
  - **점검 리포트**: 통합단말기·엔진오일·타이어 각각의 "점검 리포트 보기"에서 진입하며, 해당 계통의 **자가 점검 제출 이력을
    날짜별로**(날짜 + 확인 완료/미확인) 보여줌 — 항목별 상세가 아니라 "언제 점검했는지" 로그 형태. "제출하기"를 누르면 오늘
    날짜로 확인 완료 항목이 즉시 추가/갱신됨 (`js/app.js`의 `SELF_CHECK_LOG` mock 데이터 + `renderReportDetailContent()`)
  - 정비소 예약 (지도 목업 + 근처 정비소 5곳 → 각 항목 우측에 작은 "예약하기" 버튼 → 전화번호/전화 걸기 화면)
  - 정비 이력 (날짜·정비 항목 표 → 행 클릭 시 정비일·정비소·당시 주행거리·비용·메모 상세 화면)
- **알림**: 헤더는 차량번호만 표시(최종점검일 뺌). 공지사항 날짜·제목 표. 오늘 날짜 공지 또는 아직 확인 안 한 항목은 굵게, 확인한 건 일반 굵기로 표시.
  행을 클릭하면 본문을 모달로 확인(홈 팝업과 완전히 같은 컴포넌트 재사용 — "확인하기" 버튼 하나로 닫힘). 모달 안 날짜+제목 한 줄만 가운데 정렬
- **설정**: 헤더는 차량번호만 표시(최종점검일 뺌). 최상단 프로필 카드의 아바타를 탭하면 사진을 선택해 프로필 사진으로 등록할 수 있음
  (`FileReader`로 data URL 변환 후 `state.user.photoDataUrl`에 저장 — 새로고침하면 초기화됨, 서버 저장 아님). 사진을 등록하지 않으면
  기존처럼 닉네임/아이디 첫 글자 원형 아바타가 표시됨. 다크모드 토글, 차량정보, 로그아웃

## 공지사항 확인 흐름 (관리자 프로그램 연동 지점)

모달 상단에 "[공지사항]" 태그를 붙여 이 팝업의 종류를 명확히 표시합니다. 목록·확인 로직은 회사뷰(React 앱,
`app/public/se-notice-bridge.js`)와 실제로 연동되어 있습니다.

- **목록 합치기**: `noticeList()` (`js/app.js`)가 `window.SENotices.listForUI()`(회사뷰에서 발송한 공지, `localStorage`
  키 `se.notices.v1`을 통해 같은 오리진의 두 화면이 공유)와 이 앱의 정적 목업 `NOTICES` 배열을 합쳐 최신순으로 돌려줍니다.
  `se-notice-bridge.js`가 없으면 정적 목업만 뜹니다.
- **"오늘 하루 다시 보지 않기" 체크박스**(`localStorage`의 `se_notice_hide_until`, 날짜 하나만 저장) — 로그인 직후
  팝업을 그날 하루만 억제하는 스위치입니다. 체크하고 "확인하기"를 누르면 그날 하루는 새 공지가 와도 팝업으로 뜨지
  않습니다(알림 탭에서는 그대로 확인 가능). **체크 여부와 무관하게 "확인하기"를 누르는 순간 회사 공지는 항상 먼저
  확인 처리되므로**, 이 체크박스로 관리자에게 확인 사실이 전송되는 것 자체를 건너뛸 수는 없습니다.
- **관리자 페이지 연동 지점**: 회사가 보낸 공지(`notice.from_company === true`)는 "확인하기"를 누르는 순간
  `window.SENotices.acknowledge(notice.id)`가 불려 `se.notices.v1`의 해당 항목에 `acknowledged:true` +
  `acknowledged_at`이 즉시 기록됩니다 — 회사뷰(React) Safe 화면의 "공지 확인" 열이 이 값을 그대로 읽어 초록으로
  바뀝니다(다른 창은 `storage` 이벤트로 즉시 반영). 알림 탭에서 과거 공지 행을 클릭해 열 때도 같은 방식으로
  확인 처리되며, `acknowledge()`는 멱등이라 두 경로 모두에서 눌러도 안전합니다. 데이터 형식은 회사뷰
  `src/lib/notices.ts`와 동일합니다: `{ id, vehicle_id, message, created_at, acknowledged, acknowledged_at? }`.
- 이 앱 자체의 정적 목업 `NOTICES` 항목은 회사 공지가 아니므로(`from_company` 없음) "확인하기"를 눌러도
  `notice.read = true`만 메모리에 기록됩니다 — 새로고침하면 초기화되는 데모용 상태입니다.

## 안전운전 점수 산식 (운행 화면)

`js/app.js`의 `computeSafetyScore()` / `computePeriodSafetyScore()`가 `../PRD-06-안전운전-스코어링-모델-정리.md`에
정리된 산식을 그대로 구현합니다 — 100점에서 6개 항목(급가속/급감속/과속/차로변경/피로/환경, 배점 12·13·25·10·25·15)을
100km당 이벤트율 기준으로 감점하고, 그중 급가속·급감속·차로변경 3개 항목에만 화물 운송 특성 보정계수
(총중량 25톤↑/야간비율 50%↑/산업단지 구간/고속도로 비율 30%↑, 최대 1.55)를 나눠 적용합니다. md 문서의 6.4절
검증 예시(412km, 급가속 12·급감속 14·과속 11분 등 입력 → 67.1점/D등급) 그대로 재현되는 것을 확인했습니다.

- **건별 점수**: "일자별 운행 기록" 각 행의 점수는 그 운행 1건의 입력값만으로 계산됩니다.
- **기간 종합 점수**: 화면 상단 게이지의 점수는 개별 점수의 평균이 아니라, 평가 기간(`driveRecord.periodStart`~`periodEnd`,
  현재 2026-07)에 속한 운행 전체의 원본 입력값(이벤트 건수·과속분 등)을 전부 합산(피로는 최댓값, 비율류는 km 가중평균)한
  뒤 같은 산식을 그 "가상의 1건"에 한 번만 적용해 산출합니다. 개별 운행이 아무리 좋아도 기간 전체로 보면 과속·차로변경
  누적이 상한(25점/10점)에 걸려 더 낮게 나올 수 있는데, 이는 버그가 아니라 "합산 후 재계산" 방식의 구조적 결과입니다.
- **더미 데이터**: 급가속/급감속/과속/차로변경 건수, 최대 연속운행시간, 야간·환경미스매치·고속도로 비율, 총중량,
  산업단지 통과 여부는 아직 실측 데이터가 없어 `TRIP_LOG`의 각 운행 건마다 고정된(렌더링마다 바뀌지 않는) 현실적인
  값을 직접 넣어 두었습니다. 실 데이터 연동 시 이 필드들을 API 응답으로 교체하면 산식은 그대로 재사용됩니다.
- md 문서 자체가 임계값·보정계수를 "PoC용 초기 가정값"으로 명시하고 있어, 실측 데이터로 재조정될 수 있습니다.

## 실시간 날씨 배경 (홈 화면 · 내 트럭 박스)

`js/weather.js`가 Canvas2D로 그리는 독자적인 애니메이션이며, Three.js(3D 트럭)와는 완전히 분리된 별도 캔버스입니다
(같은 WebGL 렌더러를 공유하지 않아 모바일 GPU 부담을 늘리지 않음).

- **레이어 순서**: ① 날씨 배경(canvas, `pointer-events:none`) → ② 트럭 아이콘/문구(장차 3D 트럭으로 교체 예정) → ③ 우측 상단 날씨 배지.
  배경 캔버스는 클릭·드래그를 가로채지 않으므로 추후 이 박스에 3D 트럭이 들어와도 회전 조작에 영향이 없습니다.
- **날씨→비주얼 매핑**: 맑음(해/은은한 glow), 구름 조금/흐림(2단 깊이 구름으로 미세한 패럴랙스), 안개(레이어드 포그 밴드),
  비/강한 비(입자 수로 강도 구분), 눈(크기가 다른 입자 낙하), 뇌우(비 + 드물게 짧은 화면 밝기 flash), 맑은 밤(별 + 달).
  낮/밤 구분은 Open-Meteo가 위치 기준 일출·일몰로 계산해 주는 `is_day` 값을 그대로 사용합니다.
- **전환 효과**: 날씨가 바뀌면 하늘 색상이 즉시 바뀌지 않고 약 1.4초에 걸쳐 크로스페이드되며, 새 효과(구름/비/눈 등)는 서서히 나타납니다.
- **기온 표시 & 특보**: 실측 API가 응답하기 전이나 위치 권한이 없을 때도 "--°C"로 비지 않도록, 초기값과 시계 기반 폴백 모두
  계절에 맞는 그럴듯한 기온(8월 서울 기준 낮 31°C · 밤 25°C)을 보여줍니다. 기온이 기상청 특보 기준을 단순화한 임계값을
  넘으면 배지에 색깔 있는 특보 문구가 붙습니다 — 폭염주의보(33°C↑, 주황) · 폭염경보(35°C↑, 빨강) · 한파주의보(-12°C↓, 하늘색)
  · 한파경보(-15°C↓, 파랑). `weatherAdvisory()` (`js/weather.js`)에서 임계값을 바꿀 수 있습니다.
  URL에 `?temp=NN`을 붙이면 날씨 조건과 무관하게 표시 기온을 강제할 수 있어(`?weather=` 오버라이드와 조합 가능),
  실측 날씨를 기다리지 않고 특보 배지를 바로 데모할 수 있습니다. 예: `?weather=clear-day&temp=36`, `?weather=coldwave`.
- **접근성/성능**: `prefers-reduced-motion: reduce` 환경에서는 입자 이동과 번개 효과를 멈추고 하늘 색상만 유지합니다.
  탭이 백그라운드(`document.hidden`)일 때는 매 프레임 렌더링을 건너뜁니다.
- **개발용 날씨 오버라이드**: 실제 날씨를 기다리지 않고 URL에 `?weather=` 파라미터를 붙이면 특정 상태로 고정할 수 있습니다.
  예: `app/index.html?weather=heavy-rain`, `?weather=snow`, `?weather=fog`, `?weather=thunder`, `?weather=night`
  (전체 목록은 `js/weather.js`의 `DEBUG_WEATHER_MAP` 참고). 프로덕션에서 실수로 걸릴 일이 없도록 파라미터가 있을 때만 동작합니다.

## 데이터는 전부 mock입니다

`js/app.js` 최상단 `state.vehicle` 객체 하나만 수정하면 전체 화면 숫자가 자동으로 다시 계산됩니다.
예) 엔진오일 소진율(%), "더 급함" 배지, 다음 교체 권장일은 `lastChangeDate`/`lastChangeMileage`/`intervalKm`/`intervalDays`와
브라우저의 오늘 날짜로부터 매번 계산되는 실제 로직입니다 (하드코딩된 텍스트가 아닙니다).

## 알려진 제한사항 (백엔드 연동 전 임시 처리)

- 로그인/회원가입은 서버 통신 없이 즉시 통과합니다 (실제 인증 없음).
- 차량등록증 사진 인식은 실제 OCR이 아니라 시뮬레이션입니다 (약 1.1초 후 70% 확률로 성공한 것처럼 mock 데이터를 채움).
- 차량번호 수정은 `prompt()` 임시 UI입니다 — 실제 화면 UI로 교체 필요.
- 3D 트럭은 실제 3D 모델 파일이 아니라 Three.js로 직접 만든 프로시저럴(박스+원기둥 조합) 모델이라, 정비 상태 하이라이트는
  아직 3D 뷰에는 없습니다 (타이어 상세의 topdown 상시 라벨에만 있음).
- 타이어 상세의 topdown 그림은 6휠/8휠, 라이트/다크 4가지 조합 모두 `reference/`의 전용 이미지로 전환됩니다.
- 날씨는 브라우저 위치 권한 + [Open-Meteo](https://open-meteo.com) 무료 API로 실시간 조회하며,
  위치 권한 거부/네트워크 차단 시 현재 시각 기준 맑음(주/야간)으로 자동 대체됩니다.
- "정비소 예약"은 실제 카카오맵 SDK 연동이 아니라 스타일만 흉내낸 목업 지도 + mock 정비소 5곳입니다
  (전화번호도 가짜). 실 연동 시 `renderReserveListContent()`의 `SHOPS` 배열과 지도 부분을 교체하면 됩니다.
- "점검 리포트 보기"는 `js/app.js`의 `SELF_CHECK_LOG` mock 배열(계통별 날짜+완료여부 목록)을 그대로 보여주는 화면입니다 —
  실제로는 서버에 제출된 이력을 조회해야 하므로, 백엔드 연동 시 `renderReportDetailContent()`를 제출 이력 API 응답으로 교체하면
  됩니다. 운행 기록 상세("일자별 운행 기록" 행 클릭)는 아직 토스트 메시지만 뜨는 placeholder입니다.
- 프로필 사진은 `localStorage`가 아니라 메모리 상태에만 저장되므로 새로고침하면 사라집니다(테마 설정만 영구 저장됨).
  실 연동 시 업로드 후 서버에 저장하고 URL을 내려받는 방식으로 교체하면 됩니다.
- 운행 화면의 `driveRecord`/`TRIP_LOG`는 전부 목업입니다. 실제 운행 데이터 연동 시 `js/app.js` 상단의 이 두 값을 API 응답으로 교체하면 됩니다.
- 알림 목록 중 이 앱 자체의 정적 항목(`NOTICES`)은 목업입니다. `noticeList()`가 여기에 회사뷰가 보낸 실제 공지
  (`SENotices`)를 합쳐 최신순으로 보여주며, 그중 맨 앞 항목이 로그인 직후 팝업으로 뜨는 "오늘의 공지"입니다.
- 정비 이력(`MAINTENANCE_HISTORY`)도 목업입니다 (타이어 상세의 최근 교체일과 날짜가 서로 맞춰져 있음).
- 새로고침하면 로그인 화면으로 돌아갑니다 (세션 저장 안 함, 테마 설정만 `localStorage`에 저장됨).
